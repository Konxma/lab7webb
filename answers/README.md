# Відповіді до лабораторної роботи № 7

1. gRPC описує методи та структури даних у контракті `.proto` і зазвичай використовує бінарний Protobuf поверх HTTP/2. HTTP/2 мультиплексує потоки в одному з’єднанні. REST організовує взаємодію навколо ресурсів, часто використовує JSON і може працювати поверх різних версій HTTP.
2. Номер і тип кодування позначають поле у двійковому повідомленні. Якщо змінити номер, старі клієнти не розпізнають поле, а повторне використання номера може спотворити сенс даних. Номери вилучених полів резервують через `reserved`.
3. Скалярні типи описують окремі значення, наприклад числа, рядки чи `bool`. `enum` задає іменовані числові стани. Перше значення в proto3 має номер 0 та слугує типовим значенням. Зазвичай це `UNSPECIFIED`.
4. Unary передає один запит і одну відповідь. Server Streaming повертає потік на один запит. Client Streaming приймає потік і повертає одну відповідь. Bidirectional Streaming дозволяє потоки в обидва боки. Server Streaming підходить, наприклад, для прогресу завдання або потоку записів.
5. Обробник повертає помилку зі стандартним кодом і описом, наприклад `status.Error(codes.NotFound, "...")`. Клієнт читає код зі статусу RPC і може обробити його програмно незалежно від тексту опису.
6. Це додаткові пари ключ–значення для виклику. Власні ключі, як `x-api-key`, і службові поля gRPC передаються в заголовках HTTP/2. Сервер також може повернути кінцеві метадані в трейлерах, де передається `grpc-status`.
7. Перехоплювач отримує контекст, запит, дані методу та `handler`. Він може відхилити виклик, викликати `handler` після перевірки ключа, а після відповіді зафіксувати код і тривалість.
8. Канал сповіщає про скасування або сплив дедлайну. Обробник може завершити очікування, відписати клієнта й зупинити таймер, коли спостерігачів більше немає.
